# 계좌유형 정책 확인 · NOT TESTED · 미해결 쟁점(별도)
> 확인 주체: GrokBot 자체 검증(self-verification). 비서실장 독립 검수 결과가 아님. 상태: v5.3 개발 후보(추가 수정).

## 1. 기존 마이그레이션 정책 확인 결과
- 원장 형식(schema_version 1)에는 계좌 type 필드에 대한 별도 마이그레이션 코드가 없음. 기존 정책: type이 없으면 화면·세금 계산에서 '일반'으로 간주(`a.type||'일반'`).
- v5.2까지 저장 함수(facts)가 type을 버려, 그 시기에 저장된 원장은 ISA/IRP/연금저축으로 만든 계좌도 type 없이 저장됨 → 실제 유형 복원 근거 없음.
- v5.3(ed66d27)은 일반이 아닌 type만 저장하고 일반은 생략 → type 없음이 '일반'인지 '유실'인지 구분 불가.
- v5.3a 처리: (1) 새로 저장되는 계좌는 일반 포함 type을 명시 저장. (2) type이 없는 계좌는 '[미확인]'으로 표시하고 확인 안내를 띄움. 원장에 일반을 자동 기록하지 않음. (3) 세금 추정은 **기존 정책 그대로 일반 기준**(이 추가 지시로 세금 가정 변경 금지). (4) 유효한 type이 기록돼 있으면 그대로 유지. (5) 근거 없는 연금 등 자동 변경 없음.
- 영향: v5.3에서 일반으로 만든 계좌(type 생략 저장)도 [미확인]으로 보임. 사용자가 '관리 > 계좌 종류 확인·수정'에서 한 번 지정하면 저장됨.

## 2. 사용자 수정 경로
- 기존에는 계좌 유형을 확인·수정하는 경로가 **없었음**(새 계좌 생성 시 선택만 가능). v5.3a에서 '관리 > 계좌 종류 확인·수정' 대화상자를 추가.
- 수정 시 바뀌는 것: 해당 계좌의 type 1개 필드. 거래·배당 사용·재투자 기록, 직접 확정한 실입금액, 세전 금액은 변경 없음(qa_v53a에서 원장 비교로 확인).
- 해석 주의(대표 확인 필요): 세금 계산은 원장에서 매번 다시 계산되므로, 유형을 바꾸면 그 계좌의 **과거 지급분 자동 세후값도 새 유형 기준으로 다시 계산되어 표시**됨(기록은 바뀌지 않음, 확정 실입금액은 그대로 우선). '변경일 이후 지급분에만 새 유형 적용'(유형 이력)은 원장·세금 정책 변경이라 이번 범위에서 구현하지 않음.
- 유형 변경으로 세후 현금이 이미 사용·재투자한 금액보다 부족해지면 "세후 배당현금 부족"으로 저장을 막음.
